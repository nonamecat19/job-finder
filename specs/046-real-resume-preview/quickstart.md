# Quickstart: real resume preview validation

**Feature**: 046-real-resume-preview
**Branch**: `046-real-resume-preview`

Runnable validation scenarios that prove the feature works end-to-end. Implementation detail lives in `tasks.md` (generated by `/speckit.tasks`).

## Prerequisites

- Go 1.25+ toolchain with `GOOS=js GOARCH=wasm` support (standard in any Go 1.25+ install)
- `pnpm` + `packages/shared` built (`pnpm install && pnpm --filter @job-finder/shared build`)
- The dashboard dev server running (`make dev` or equivalent) with a seeded generation run available (`make seed`)
- A browser with WebAssembly support (any current Chrome/Firefox/Safari/Edge)

## Scenario 1 — preview-document endpoint returns the same YAML export would assemble (FR-001, contracts/preview-document.md)

**Proves**: the new endpoint is a strict subset of the export pipeline — same assembly, same serialization, no drift.

```sh
cd apps/api
go test ./internal/generation/application/ -run TestPreviewDocument_MatchesExportAssembly -v
```

**Expected**: PASS. The test calls both the new preview-document use case and `renderExport`'s assembly step on the same run/sections fixture and asserts the YAML text is identical up to the fields `ApplyFontSize` would otherwise mutate (which the preview path never calls).

## Scenario 2 — the browser build of `pkg/rendercv` produces Typst source (Decision 1)

**Proves**: the `GOOS=js GOARCH=wasm` build of `ReadYAML`/`Build`/`GenerateTypst` runs headlessly (Node or a browser test harness) and matches the server build's output for the same input.

```sh
cd ../rendercv-go
GOOS=js GOARCH=wasm go build -o dist/rendercv.wasm ./cmd/wasm   # new build target added by this feature
go test -run TestWasmBuild_GenerateTypst_MatchesServerBuild ./... -v
```

**Expected**: PASS. Same `.typ` output as the existing server-side `GenerateTypst` call for `testdata/golden`'s fixture documents.

## Scenario 3 — live preview in the Generate page matches the exported PDF (spec User Story 1, SC-001, SC-002)

**Proves**: what the user sees in the preview pane is what they get from export/download.

1. Open the Generate page for a seeded generation run.
2. Confirm the preview pane shows a loading state, then a rendered PDF (FR-005).
3. Toggle a section off, then on. Confirm the preview updates within a few seconds and does not flicker mid-edit (FR-003, FR-010).
4. Click Export/Download and open the resulting PDF.
5. Compare the two PDFs: same section order, same page count, same theme/locale formatting (SC-001, SC-002).

**Expected**: visually identical, matching page count.

## Scenario 4 — preview failure doesn't block export (User Story 3, FR-006, FR-007)

**Proves**: a broken preview never blocks the user's actual goal (getting a PDF).

1. Force a preview rendering failure (e.g. temporarily corrupt the WASM asset path in dev tools, or simulate via the `previewPipeline.ts` unit tests' error-injection case).
2. Confirm the preview pane shows a clear error state, not a blank pane and not stale content passed off as current.
3. Confirm Export/Download still works and produces a correct PDF.

```sh
cd apps/dashboard
pnpm vitest run src/features/generate/wasm/previewPipeline.test.ts
```

**Expected**: PASS, including the error-injection case; Export/Download path is untouched by the failure (asserted by keeping the export mutation test in the same suite unaffected).

## Scenario 5 — cold-load cost is isolated from the per-edit budget (research.md, Open risk)

**Proves**: first-load WASM/font download doesn't count against the 3-second SC-003 target, and is cached thereafter.

1. Clear the browser's Cache API storage for the dashboard origin.
2. Load the Generate page; measure time to first rendered preview (expected: dominated by the ~29 MB `typstwasm` + font download, not bounded by SC-003).
3. Reload the page (cache warm). Measure time to first rendered preview — expected: no re-download, load time drops to near-instant WASM instantiation.
4. With the cache warm, toggle a section and measure time to updated preview — expected: within 3 seconds (SC-003), the metric actually gated.
